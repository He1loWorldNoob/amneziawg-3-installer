# Руководство по использованию

Что делать с сервером после того, как он развёрнут: выдавать ключи, следить за
связью, менять параметры, разбираться с проблемами. Как развернуть — в
[«Установке от и до»](install.md).

---

## Перед началом

Установка — в отдельном документе: [«Установка от и до»](install.md). Там
требования к серверу, три команды развёртывания от пустой машины до выданного
ключа и что делать, если на каком-то шаге не пошло.

Здесь — всё, что после: управление ключами, повседневная эксплуатация, смена
параметров сервера, интерфейсы, типовые проблемы и удаление.

## 1. Управление клиентами

После установки доступна команда `awg3` из любого каталога.

### Создать клиента

```bash
sudo awg3 add my_phone
```

Появится каталог со всем нужным:

```
~/awg/my_phone/my_phone.conf      конфиг
~/awg/my_phone/my_phone.png       QR-код для мобильного приложения
~/awg/my_phone/my_phone.vpnuri    ссылка vpn:// для приложения Amnezia
~/awg/my_phone/my_phone.private   приватный ключ
~/awg/my_phone/my_phone.public    публичный ключ
```

Отдать клиенту целиком одной папкой:

```bash
scp -P 2222 -r vpnadmin@СЕРВЕР:~/awg/my_phone ./
```

Или показать QR прямо в терминале и отсканировать приложением:

```bash
sudo qrencode -t ansiutf8 < ~/awg/my_phone/my_phone.conf
```

### Ссылка vpn://

Файл `ИМЯ.vpnuri` — одна строка вида `vpn://...`, которую приложение
AmneziaVPN принимает в «+» → «Ввести ключ вручную». Внутри тот же самый
конфиг: ссылка собирается из него, поэтому разойтись им негде.

Клиентам, выданным раньше, ссылку можно собрать по готовому конфигу — ключи
и пир при этом не трогаются:

```bash
sudo awg3 link my_phone     # одному: файл рядом с конфигом, ссылка на экран
sudo awg3 link              # всем сразу, без вывода ссылок на экран
```

Ссылка содержит приватный ключ клиента ровно так же, как конфиг и QR:
передавать её стоит теми же каналами.

Параметры AWG 3.0, которых нет в формате ссылки (`HeaderProtectionKey`,
`ContentPaddingAddition`, таймеры), кладутся в неё отдельными полями и
целиком внутрь встроенного текста конфига. Приложение, которое их не знает,
лишние поля проигнорирует — с такими клиентами остаются `.conf` и QR.

Не нужна вовсе — `sudo awg3 add my_phone --no-link`.

**Полезные флаги `add`:**

```bash
# другой профиль мимикрии для этого клиента
sudo awg3 add work_laptop -p tls -i high

# роутер или слабое железо: минимум шума
sudo awg3 add home_router --router

# только трафик до конкретных сетей, остальное мимо VPN
sudo awg3 add partial --allowed-ips "10.0.0.0/8, 192.168.1.0/24"

# свой DNS
sudo awg3 add my_phone --dns "9.9.9.9, 149.112.112.112"

# явно указать адрес сервера, если автоопределение ошибается
sudo awg3 add my_phone --endpoint vpn.example.com
```

### Посмотреть, кто есть

```bash
sudo awg3 list
```

```
КЛИЕНТ               АДРЕС          ВЕРСИЯ СВЯЗЬ          РАСКЛАДКА СОВМЕСТИМ
-------------------------------------------------------------------------------
my_phone             10.9.9.2/32    3.0    активен        папка     да
my_laptop            10.9.9.3/32    3.0    был 3ч назад   папка     да

Интерфейс awg0: AWG 3.1 (S1=97 H1=651725171-651746509, RandomTrailers on)
  порт: 48872/udp, подсеть: 10.9.9.1/24, MTU: 1280
  изоляция клиентов: off, IPv6: off
```

Колонка **СОВМЕСТИМ** — главная. `нет — клиент не подключится` означает, что
общие параметры клиента разошлись с серверными: конфиг выдан до
`server-rekey` или `reinstall` и его надо пересоздать.

Строки про сервер читаются из самого `awg0.conf`, так что показывают
фактическое положение дел, а не то, что когда-то было задано при установке.

### Трафик и активность

```bash
sudo awg3 stats
```

### Удалить клиента

```bash
sudo awg3 remove my_phone
```

Покажет полный список того, что будет удалено, и спросит подтверждение.
Приватный ключ затирается через `shred`, а не просто удаляется.

Можно несколько сразу: `sudo awg3 remove old_phone old_laptop`.

### Резервная копия

```bash
sudo awg3 backup
```

Архив с конфигом сервера, ключами и всеми каталогами клиентов ляжет в
`~/awg/backups/`. Старые архивы сами не удаляются — только явно:

```bash
sudo awg3 backup --prune 5   # оставить 5 последних, остальные удалить
```

## 2. Повседневная эксплуатация

```bash
sudo awg3 show                        # состояние интерфейса
sudo awg3 restart                     # перезапустить туннель
systemctl status awg-quick@awg0       # состояние сервиса
sudo ufw status verbose               # правила фаервола
sudo tail -f ~/awg/awg3.log           # журнал операций awg3
```

### После обновления ядра

Модуль пересобирается автоматически — этим занимаются
`/usr/local/sbin/amneziawg-ensure-module`, юнит `amneziawg-ensure-module.service`
и apt-хук `/etc/apt/apt.conf.d/99-amneziawg-post-kernel`. Проверить:

```bash
sudo dkms status
lsmod | grep amneziawg
```

Если после перезагрузки туннель не поднялся:

```bash
sudo /usr/local/sbin/amneziawg-ensure-module --systemd
sudo systemctl restart awg-quick@awg0
```

### Диагностический отчёт

```bash
sudo ./install-awg3.sh --diagnostic
```

Отчёт ляжет в `~/awg/diag_ДАТА.txt`. Приватный ключ, `HeaderProtectionKey` и
`PresharedKey` в нём скрыты, но **IP-адреса, порты и маршруты остаются** —
просмотрите файл перед тем, как выкладывать его публично.

## 3. Изменение конфигурации сервера

Важно понимать цену: `S1-S4`, `H1-H4` и `HeaderProtectionKey` обязаны
совпадать на обоих концах. Их перегенерация делает **все ранее выданные
конфиги нерабочими**.

| Задача | Команда | Клиенты выживают? |
|---|---|---|
| Добавить/убрать клиента | `awg3 add` / `awg3 remove` | да |
| Сменить имя хоста в новых конфигах | `awg3 set-endpoint` | да, выданные продолжают работать по прежнему адресу |
| Переселить клиента на другой интерфейс | `awg3 migrate-client` | да, см. раздел 4 |
| Сменить общие параметры обфускации | `awg3 server-rekey` | **нет** |
| Сменить порт, подсеть, изоляцию, IPv6 | `awg3 iface remove` и следом `iface add` | **нет**, интерфейс создаётся с нуля |

Отдельной команды «поменять порт» нет намеренно. Она делала бы вид, что правит
одно поле, а на деле пересобирала бы интерфейс целиком — с новыми ключами
сервера и новыми параметрами обфускации. Пересоздание должно выглядеть как
пересоздание: снести и создать.

Установщик в этом не участвует: он ставит пакеты и модуль, а всё, что меняет
конфигурацию, живёт в `awg3`. Оба разрушительных сценария предупреждают и
требуют подтверждения. После них:

```bash
sudo awg3 list                 # СОВМЕСТИМ покажет «нет» у всех старых
sudo awg3 remove старый_клиент
sudo awg3 add старый_клиент    # выдать новый конфиг
```

## 4. Несколько интерфейсов и параметры 3.1

### Что нового в 3.1

Два параметра, оба пишутся в секцию `[Interface]`:

| Параметр | Что делает | Односторонний? |
|---|---|---|
| `RandomTrailers` | дописывает к служебным пакетам случайный хвост, снимая постоянную длину рукопожатия | **нет**, обязан совпадать на сервере и всех его клиентах |
| `DisableCookies` | запрещает отвечать на cookie-запросы | да, включается на любом конце независимо |

Без `RandomTrailers` пакет инициации всегда 148+S1 байт, а ответ 92+S2 — сервер
опознаётся по одному пакету. С ним приёмник переходит с проверки «длина равна
ожидаемой» на «не меньше ожидаемой», поэтому **включённый только на одной
стороне он рвёт туннель полностью**. Отсюда правило: клиент повторяет параметр
за сервером, как S1-S4 и `HeaderProtectionKey`.

Выключателей у них нет: 3.0 из проекта убран, интерфейс либо 3.1, либо не наш.
Нужен клиент Amnezia **5.0.1.5 или новее**.

Сервер сам проверяет версии до записи конфига: если модуль в памяти или
`amneziawg-tools` старше 3.1, команда останавливается и объясняет, чего не
хватает — обновления пакетов или перезагрузки. Конфиг с `RandomTrailers` на
модуле 3.0 ломает не текущий, а **следующий** запуск сервиса, поэтому проверка
идёт до записи.

### Интерфейс, созданный до 3.1

Если сервер разворачивали раньше, в его `awg0.conf` нет строки
`RandomTrailers`. Выдать на таком интерфейсе клиента 3.1 нельзя, и `awg3` этого
не даст:

```
[ОШИБКА] интерфейс awg0 создан до 3.1: в /etc/amnezia/amneziawg/awg0.conf нет RandomTrailers.
[ОШИБКА] Выдать на нём клиента 3.1 нельзя — туннель молча не встанет.
[ОШИБКА] Переведите интерфейс: awg3 --iface awg0 server-rekey
```

Отказ здесь дороже любого другого молчания: клиент получил бы `RandomTrailers`,
которого нет у сервера, и туннель не встал бы **вообще** — без ошибки, без
единого пакета. Отличить это от «провайдер режет» невозможно.

`server-rekey` переводит интерфейс на 3.1. Выборочно перевести одного клиента
нельзя — параметры интерфейса общие для всех, поэтому конфиги выдаются заново.
`awg3 iface` показывает такие интерфейсы в колонке версии.

### Несколько интерфейсов на одном сервере

Интерфейсы независимы: свой порт, своя подсеть, свои общие параметры и свой
каталог клиентов. `awg0` живёт в каталоге скрипта (`~/awg`), остальные — в
соседнем каталоге по имени: `~/awg1/ИМЯ/ИМЯ.conf`.

```bash
# что вообще есть на сервере
sudo awg3 iface

# создать — имя берётся первое свободное, порт в ufw открывается сам
sudo awg3 iface add --awg-port 51840 --subnet 10.9.1.1/24

# или с явным именем
sudo awg3 iface add awg1 --awg-port 51840 --subnet 10.9.1.1/24

# клиент на нём
sudo awg3 --iface awg1 add ivan

# снести вместе с клиентами и ключами
sudo awg3 iface remove awg1
```

`iface list` — то же, что прежняя команда `ifaces`; `iface add` — то же, что
`--iface awgN server-init`. Старые имена работают дальше.

`--iface` относится ко всему вызову и принимается как перед командой, так и
после неё. Одинаковые имена клиентов на разных интерфейсах допустимы — на этом
держится переезд.

### Переезд клиента без простоя

```bash
sudo awg3 --iface awg0 migrate-client ivan --to awg1
```

Клиент заводится на `awg1` с **тем же ключом**: на сервере это остаётся тот же
пир, у человека — та же личность. Меняются общие параметры, адрес в туннеле и
порт.

С исходного интерфейса клиент намеренно **не удаляется**. Пока он там есть,
прежняя ссылка продолжает работать, и человек переезжает в тот момент, когда
сам импортирует новую. Когда переехал — уберите старого пира:

```bash
sudo awg3 --iface awg0 remove ivan
```

Зачем это нужно: если один интерфейс попал под блокировку по набору параметров,
второй с другими `S1-S4` и другим портом поднимается заранее, и переезд не
требует одновременного участия человека на той стороне.

## 5. Типовые проблемы

### Клиент подключается, но интернета нет

Проверьте форвардинг и NAT:

```bash
sysctl net.ipv4.ip_forward              # должно быть 1
sudo iptables -t nat -S POSTROUTING | grep MASQUERADE
sudo awg show awg0                      # есть ли рукопожатие
```

Если `MASQUERADE` указывает не на тот интерфейс — сервер сменил NIC. Внешний
интерфейс запоминается в `PostUp` при создании, поэтому лечится пересозданием:
`awg3 iface remove awg0`, затем `awg3 iface add awg0`. Ключи придётся выдать
заново.

### Ping идёт, а сайты не открываются

Классика — не работает подгонка MSS. Проверьте, что в `PostUp` есть правила
`TCPMSS`, и попробуйте MTU поменьше:

```bash
sudo awg3 list                    # текущий MTU
sudo awg3 iface remove awg0
sudo awg3 iface add awg0 --mtu 1240
```

MTU лежит и в серверном конфиге, и в клиентских, поэтому меняется он вместе с
пересозданием интерфейса — ключи выдаются заново.

### Клиент вообще не подключается

```bash
sudo awg3 list          # колонка СОВМЕСТИМ
sudo ufw status | grep udp
sudo ss -ulnp | grep awg
```

Три частые причины: конфиг выдан до перегенерации параметров; UDP-порт закрыт
на фаерволе провайдера; в конфиге клиента неверный `Endpoint` — исправляется
выдачей нового с `--endpoint`.

### Клиенты не видят друг друга (или видят, а не должны)

```bash
sudo awg3 list                                   # строка «изоляция клиентов»
sudo iptables -S FORWARD | grep awg0             # правило DROP
```

Сменить можно только пересозданием интерфейса:

```bash
sudo awg3 iface remove awg0
sudo awg3 iface add awg0 --isolation on
```

### Модуль не грузится

```
modprobe: ERROR: could not insert 'amneziawg': Key was rejected by service
```

Включён Secure Boot. Как его выключить — в [«Установке от и до»](install.md).

### Потерян доступ по SSH

`bootstrap.sh` устроен так, чтобы этого не случилось: старый порт остаётся
открытым до подтверждения, конфигурация проверяется до перезапуска, а если
sshd не начал слушать новый порт — изменения откатываются автоматически.

Если всё же заперлись, через консоль гипервизора:

```bash
rm -f /etc/ssh/sshd_config.d/99-awg3-hardening.conf
rm -f /etc/systemd/system/ssh.socket.d/99-awg3-port.conf
systemctl daemon-reload
systemctl restart ssh.socket ssh
ufw allow 22/tcp
```

## 6. Удаление

```bash
sudo ./install-awg3.sh --uninstall
```

Снимает AmneziaWG, его пакеты, правила фаервола и sysctl. **Не трогает** то,
что сделал `bootstrap.sh`: пользователь, SSH-порт и состояние root-логина
остаются как есть. Каталог `~/awg` с ключами и конфигами клиентов тоже
сохраняется — удалите вручную, если он больше не нужен:

```bash
sudo find ~/awg -name '*.private' -exec shred -u {} +
sudo rm -rf ~/awg
```

## 7. Справочник команд

Три скрипта, три задачи:

| Скрипт | Задача |
|---|---|
| `bootstrap.sh` | подготовка системы: пользователь, SSH, фаервол, fail2ban, swap, sysctl |
| `install-awg3.sh` | пакеты, модуль ядра, `awg3` в `PATH`. Ни систему, ни конфигурацию не трогает |
| `awg3` | интерфейсы и клиенты |

Команды `awg3`, сгруппированные по тому, к чему относятся:

| Об интерфейсах | |
|---|---|
| `iface` | список интерфейсов: порт, подсеть, версия, сколько ключей |
| `iface add [ИМЯ]` | создать; без имени берётся первое свободное |
| `iface remove ИМЯ` | снести вместе с ключами |
| `server-rekey` | новые общие параметры обфускации |
| `set-endpoint ХОСТ` | имя хоста для новых клиентских конфигов |
| `show`, `restart` | `awg show` и перезапуск сервиса |

| О ключах | |
|---|---|
| `add ИМЯ` | выдать ключ: conf, QR, ссылка `vpn://` |
| `remove ИМЯ...` | удалить ключ вместе с пиром и файлами |
| `list` | таблица для чтения: адрес, связь, совместимость |
| `peers` | то же колонками через табуляцию — для скриптов и панели |
| `names` | только имена, по одному в строке |
| `stats` | трафик и последняя активность |
| `link [ИМЯ...]` | пересобрать ссылку `vpn://` по готовому конфигу |
| `migrate-client ИМЯ --to ИНТЕРФЕЙС` | переселить с сохранением ключа |

| О сервере целиком | |
|---|---|
| `backup [--prune N]` | архив конфигов и ключей в `~/awg/backups` |
| `migrate` | разложить клиентов из прежней схемы по каталогам |
| `gen` | просто выдать набор параметров обфускации |

`--iface ИМЯ` адресует любую команду конкретному интерфейсу и принимается как
перед ней, так и после: `awg3 --iface awg1 add ivan`.

```bash
./bootstrap.sh --help
./install-awg3.sh --help
awg3 --help
```
