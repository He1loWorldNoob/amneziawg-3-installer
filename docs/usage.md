# Руководство по использованию

Подробная инструкция: от чистого сервера до выданного клиента и повседневной
эксплуатации. Краткая версия — в [README](../README.md).

---

## 1. Что нужно до начала

| Требование | Как проверить |
|---|---|
| Debian 12/13 или Ubuntu 22.04+ | `cat /etc/os-release` |
| Обычная ВМ, не LXC | `systemd-detect-virt` — должно быть `kvm`, `qemu`, `none`, но не `lxc` |
| **Secure Boot выключен** | `mokutil --sb-state` → `SecureBoot disabled` |
| Есть интернет и DNS | `getent hosts deb.debian.org` |
| Доступ root по SSH | вход работает |
| Свободно ≥ 2 ГБ | `df -h /` |

**Про Secure Boot.** Модуль AmneziaWG собирается через DKMS и не подписан. При
включённом Secure Boot ядро откажется его грузить:

```
modprobe: ERROR: could not insert 'amneziawg': Key was rejected by service
```

Выключите Secure Boot в BIOS/UEFI (в Proxmox — Hardware → BIOS: OVMF, снять
галку Secure Boot). Альтернатива — enroll собственного MOK-ключа, но это
интерактивная процедура при каждой загрузке.

**Как получить файлы на сервере.** Всё выполняется на самом сервере, копировать
с локальной машины ничего не нужно:

```bash
# без git — на свежем сервере его может не быть
curl -fsSL https://github.com/He1loWorldNoob/amneziawg-3-installer/archive/refs/heads/main.tar.gz \
  | tar -xz && cd amneziawg-3-installer-main

# либо, если git установлен
git clone https://github.com/He1loWorldNoob/amneziawg-3-installer.git
cd amneziawg-3-installer
```

Если между шагами вы меняли пользователя (`bootstrap.sh` создаёт нового),
скачайте репозиторий заново уже под ним — каталог остаётся в домашней папке
того, кто скачивал.

## 2. Развёртывание

### Способ 1: два шага (рекомендуется)

Между шагами вы переподключаетесь под новым пользователем — это и есть
проверка, что доступ работает, до того как root будет закрыт.

**Шаг 1 — подготовка системы:**

```bash
sudo ./bootstrap.sh --user admin --ssh-port 2222 --disable-root-ssh yes
```

Скрипт спросит пароль для нового пользователя (дважды) и, перед отключением
root, остановится с требованием проверить новый доступ:

```
СЕЙЧАС БУДЕТ ОТКЛЮЧЁН ВХОД ROOT ПО SSH.
Текущая сессия жива, но НЕ ЗАКРЫВАЙТЕ ЕЁ.
Откройте ВТОРОЕ окно терминала и проверьте:

    ssh -p 2222 admin@203.0.113.10
    sudo -v

Вход и sudo работают? Введите yes целиком:
```

Откройте второе окно, проверьте, и только тогда отвечайте `yes` (целиком, не
`y`). Любой другой ответ оставит root включённым — ничего страшного не
произойдёт, просто закроете его потом вручную.

Итог сохранится в `~/awg3-bootstrap-summary.txt`. **Пароль восстановить
нельзя** — сохраните его.

**Шаг 2 — установка AmneziaWG** (уже под новым пользователем):

```bash
ssh -p 2222 admin@СЕРВЕР
cd awg3-deploy
sudo ./install-awg3.sh --mode awg-only
```

Скрипт спросит параметры сервера, поставит пакеты, соберёт модуль ядра,
настроит фаервол и создаст конфигурацию.

### Способ 2: одной командой с меню

```bash
sudo ./install-awg3.sh
```

```
  1) Полное развёртывание с нуля     подготовка системы + AmneziaWG 3.0
  2) Только AmneziaWG 3.0            система уже подготовлена
  3) Перевести 2.0-сервер на 3.0     клиентов придётся создать заново
  4) Переустановить поверх           пиры сохраняются, параметры новые
  5) Удалить                         снести AmneziaWG
```

### Способ 3: полностью без вопросов

```bash
printf 'мой-пароль-минимум-8-символов\n' > /root/pw && chmod 600 /root/pw

sudo ./install-awg3.sh --mode full \
    --user admin --password-file /root/pw \
    --ssh-port 2222 --disable-root-ssh yes \
    --awg-port 48872 --subnet 10.9.9.1/24 --mtu 1280 \
    --isolation off --ipv6 off \
    --profile quic --intensity medium \
    --clients my_phone,my_laptop --yes

shred -u /root/pw
```

**Пароль нельзя передать аргументом** — только файлом или интерактивно:
аргументы командной строки видны в `ps` любому пользователю системы и
оседают в истории shell.

С `--yes` пропускается и пауза-подтверждение перед отключением root. Годится
для автоматизации, но при ошибке в параметрах доступ к серверу теряется —
держите наготове консоль гипервизора.

### Что означают параметры

| Параметр | Дефолт | Смысл |
|---|---|---|
| `--awg-port` | случайный 1024–65000 | UDP-порт. Предсказуемый порт — лишний признак для анализатора трафика |
| `--subnet` | `10.9.9.1/24` | адрес сервера внутри туннеля с маской. Именно адрес хоста, не сети |
| `--mtu` | `1280` | MTU туннеля. 1280 безопасен почти везде; выше — быстрее, но рискует фрагментацией |
| `--isolation` | `off` | `on` — клиенты не видят друг друга (правило `DROP` между ними) |
| `--ipv6` | `off` | `on` — выдавать клиентам IPv6 и настроить `ip6tables` |
| `--profile` | `quic` | под какой протокол мимикрирует первый пакет |
| `--intensity` | `medium` | сколько мусорного трафика подмешивать |
| `--endpoint` | внешний IP | имя хоста, которое попадёт клиентам в `Endpoint`; синоним `--host-name` |
| `--clients` | пусто | создать клиентов сразу после установки |

### Про имя хоста

Установщик спрашивает его отдельно, и это стоит заполнить, если у сервера
есть DNS-имя:

```
Имя хоста для клиентов — адрес, который попадёт в Endpoint выданных
конфигов. Укажите DNS-имя (vpn.example.com), если оно есть: тогда при
смене IP сервера старые конфиги продолжат работать.
```

Имя сохраняется прямо в `awg0.conf` строкой `#_Endpoint = имя` — по образцу
`#_Name` у пиров, так что отдельного файла настроек по-прежнему нет. Оно
переживает `reinstall`, видно в `awg3 list` и используется всеми последующими
`awg3 add`. Перекрыть для конкретного клиента можно флагом:

```bash
sudo awg3 add my_phone --endpoint vpn2.example.com
```

Если имя не задано, адрес определяется по цепочке: `Endpoint` уже
существующего клиента → внешний IP через ipify.

## 3. Управление клиентами

После установки доступна команда `awg3` из любого каталога.

### Создать клиента

```bash
sudo awg3 add my_phone
```

Появится каталог со всем нужным:

```
~/awg/my_phone/my_phone.conf      конфиг
~/awg/my_phone/my_phone.png       QR-код для мобильного приложения
~/awg/my_phone/my_phone.private   приватный ключ
~/awg/my_phone/my_phone.public    публичный ключ
```

Отдать клиенту целиком одной папкой:

```bash
scp -P 2222 -r admin@СЕРВЕР:~/awg/my_phone ./
```

Или показать QR прямо в терминале и отсканировать приложением:

```bash
sudo qrencode -t ansiutf8 < ~/awg/my_phone/my_phone.conf
```

**Полезные флаги `add`:**

```bash
# другой профиль мимикрии для этого клиента
sudo awg3 add work_laptop -p tls -i high

# роутер или слабое железо: минимум шума
sudo awg3 add home_router --router

# только трафик до конкретных сетей, остальное мимо VPN
sudo awg3 add partial --allowed-ips "10.0.0.0/8, 192.168.1.0/24"

# свой DNS
sudo awg3 add my_phone --dns "9.9.9.9, 149.112.112.112"

# явно указать адрес сервера, если автоопределение ошибается
sudo awg3 add my_phone --endpoint vpn.example.com
```

### Посмотреть, кто есть

```bash
sudo awg3 list
```

```
КЛИЕНТ               АДРЕС          ВЕРСИЯ СВЯЗЬ          РАСКЛАДКА СОВМЕСТИМ
-------------------------------------------------------------------------------
my_phone             10.9.9.2/32    3.0    активен        папка     да
my_laptop            10.9.9.3/32    3.0    был 3ч назад   папка     да

Сервер: AWG 3.0 (S1=97 H1=651725171-651746509)
  порт: 48872/udp, подсеть: 10.9.9.1/24, MTU: 1280
  изоляция клиентов: off, IPv6: off
```

Колонка **СОВМЕСТИМ** — главная. `нет — клиент не подключится` означает, что
общие параметры клиента разошлись с серверными: конфиг выдан до
`server-upgrade` или `reinstall` и его надо пересоздать.

Строки про сервер читаются из самого `awg0.conf`, так что показывают
фактическое положение дел, а не то, что когда-то было задано при установке.

### Трафик и активность

```bash
sudo awg3 stats
```

### Удалить клиента

```bash
sudo awg3 remove my_phone
```

Покажет полный список того, что будет удалено, и спросит подтверждение.
Приватный ключ затирается через `shred`, а не просто удаляется.

Можно несколько сразу: `sudo awg3 remove old_phone old_laptop`.

### Резервная копия

```bash
sudo awg3 backup
```

Архив с конфигом сервера, ключами и всеми каталогами клиентов ляжет в
`~/awg/backups/`. Старые архивы сами не удаляются — только явно:

```bash
sudo awg3 backup --prune 5   # оставить 5 последних, остальные удалить
```

## 4. Повседневная эксплуатация

```bash
sudo awg3 show                        # состояние интерфейса
sudo awg3 restart                     # перезапустить туннель
systemctl status awg-quick@awg0       # состояние сервиса
sudo ufw status verbose               # правила фаервола
sudo tail -f ~/awg/awg3.log           # журнал операций awg3
```

### После обновления ядра

Модуль пересобирается автоматически — этим занимаются
`/usr/local/sbin/amneziawg-ensure-module`, юнит `amneziawg-ensure-module.service`
и apt-хук `/etc/apt/apt.conf.d/99-amneziawg-post-kernel`. Проверить:

```bash
sudo dkms status
lsmod | grep amneziawg
```

Если после перезагрузки туннель не поднялся:

```bash
sudo /usr/local/sbin/amneziawg-ensure-module --systemd
sudo systemctl restart awg-quick@awg0
```

### Диагностический отчёт

```bash
sudo ./install-awg3.sh --diagnostic
```

Отчёт ляжет в `~/awg/diag_ДАТА.txt`. Приватный ключ, `HeaderProtectionKey` и
`PresharedKey` в нём скрыты, но **IP-адреса, порты и маршруты остаются** —
просмотрите файл перед тем, как выкладывать его публично.

## 5. Изменение конфигурации сервера

Важно понимать цену: `S1-S4`, `H1-H4` и `HeaderProtectionKey` обязаны
совпадать на обоих концах. Их перегенерация делает **все ранее выданные
конфиги нерабочими**.

| Задача | Команда | Клиенты выживают? |
|---|---|---|
| Добавить/убрать клиента | `awg3 add` / `awg3 remove` | да |
| Сменить порт, подсеть, изоляцию, IPv6 | `install-awg3.sh --mode reinstall` | **нет**, пиры переносятся, но конфиги надо выдать заново |
| Перевести старый 2.0-сервер на 3.0 | `install-awg3.sh --mode upgrade` | **нет** |

Оба сценария предупреждают об этом и требуют подтверждения. После них:

```bash
sudo awg3 list                 # СОВМЕСТИМ покажет «нет» у всех старых
sudo awg3 remove старый_клиент
sudo awg3 add старый_клиент    # выдать новый конфиг
```

## 6. Типовые проблемы

### Клиент подключается, но интернета нет

Проверьте форвардинг и NAT:

```bash
sysctl net.ipv4.ip_forward              # должно быть 1
sudo iptables -t nat -S POSTROUTING | grep MASQUERADE
sudo awg show awg0                      # есть ли рукопожатие
```

Если `MASQUERADE` указывает не на тот интерфейс — сервер сменил NIC. Лечится
пересозданием: `install-awg3.sh --mode reinstall`.

### Ping идёт, а сайты не открываются

Классика — не работает подгонка MSS. Проверьте, что в `PostUp` есть правила
`TCPMSS`, и попробуйте MTU поменьше:

```bash
sudo awg3 list                    # текущий MTU
sudo ./install-awg3.sh --mode reinstall --mtu 1240
```

### Клиент вообще не подключается

```bash
sudo awg3 list          # колонка СОВМЕСТИМ
sudo ufw status | grep udp
sudo ss -ulnp | grep awg
```

Три частые причины: конфиг выдан до перегенерации параметров; UDP-порт закрыт
на фаерволе провайдера; в конфиге клиента неверный `Endpoint` — исправляется
выдачей нового с `--endpoint`.

### Клиенты не видят друг друга (или видят, а не должны)

```bash
sudo awg3 list                                   # строка «изоляция клиентов»
sudo iptables -S FORWARD | grep awg0             # правило DROP
```

Сменить можно только пересозданием сервера:

```bash
sudo ./install-awg3.sh --mode reinstall --isolation on
```

### Модуль не грузится

```
modprobe: ERROR: could not insert 'amneziawg': Key was rejected by service
```

Включён Secure Boot — см. раздел 1.

### Потерян доступ по SSH

`bootstrap.sh` устроен так, чтобы этого не случилось: старый порт остаётся
открытым до подтверждения, конфигурация проверяется до перезапуска, а если
sshd не начал слушать новый порт — изменения откатываются автоматически.

Если всё же заперлись, через консоль гипервизора:

```bash
rm -f /etc/ssh/sshd_config.d/99-awg3-hardening.conf
rm -f /etc/systemd/system/ssh.socket.d/99-awg3-port.conf
systemctl daemon-reload
systemctl restart ssh.socket ssh
ufw allow 22/tcp
```

## 7. Удаление

```bash
sudo ./install-awg3.sh --uninstall
```

Снимает AmneziaWG, его пакеты, правила фаервола и sysctl. **Не трогает** то,
что сделал `bootstrap.sh`: пользователь, SSH-порт и состояние root-логина
остаются как есть. Каталог `~/awg` с ключами и конфигами клиентов тоже
сохраняется — удалите вручную, если он больше не нужен:

```bash
sudo find ~/awg -name '*.private' -exec shred -u {} +
sudo rm -rf ~/awg
```
