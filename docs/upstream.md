# Апстрим и наши правки

## Источники

| Файл в `vendor/` | Откуда | Версия | Дата |
|---|---|---|---|
| `install_amneziawg_en.sh` | [bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer) | 5.23.0 | 2026-07-31 |
| `awg_common_en.sh` | там же, тег `v5.23.0` | 5.23.0 | 2026-07-31 |
| `awg3-apply.sh` | локальный одноразовый скрипт переноса конфигов на 3.0 | — | 2026-08-04 |

`awg3.sh` в корне — собственный скрипт, исторически вобравший генератор
параметров из
[Vadim-Khristenko/AmneziaWG-Architect](https://github.com/Vadim-Khristenko/AmneziaWG-Architect)
(`awg-gen.sh`). Кодовой зависимости от Architect нет.

`vendor/` в работе не участвует. Он нужен, чтобы при выходе новой версии
апстрима увидеть через `git diff`, что изменилось у bivlked, и решить,
переносить ли это к себе.

## Как обновлять апстрим

```bash
curl -fsSL -o vendor/install_amneziawg_en.sh \
    https://raw.githubusercontent.com/bivlked/amneziawg-installer/vX.Y.Z/install_amneziawg_en.sh
curl -fsSL -o vendor/awg_common_en.sh \
    https://raw.githubusercontent.com/bivlked/amneziawg-installer/vX.Y.Z/awg_common_en.sh
git diff vendor/
```

Дальше вручную решить, что из изменений переносить в `install-awg3.sh`.

## Три скрипта вместо одного

Апстрим — один скрипт, который делает всё: готовит систему, ставит пакеты,
собирает модуль, создаёт сервер и выдаёт клиентов. У нас это разведено по
границе «чьё это решение»:

| Скрипт | Задача |
|---|---|
| `bootstrap.sh` | как настроена машина: пользователь, SSH, фаервол, fail2ban, обновление системы, swap, sysctl |
| `install-awg3.sh` | пакеты AmneziaWG, DKMS-модуль, `awg3` в `PATH`. Больше ничего |
| `awg3.sh` | интерфейсы и клиенты: создание, ключи, переезды, смена параметров |

Установщик AmneziaWG не решает, как настроен чужой сервер, и не создаёт
конфигурацию VPN — этим заняты соседи слева и справа.

### Изменено

| Что | Как |
|---|---|
| `AWG_DIR` | вместо константы `/root/awg` — функция `resolve_awg_dir()`: домашний каталог целевого пользователя (`SUDO_USER`), либо `/root/awg`; перекрывается `--awg-dir` и `AWG3_DIR` |
| источник истины | только `/etc/amnezia/amneziawg/<интерфейс>.conf` |
| требование к ядру | младше 6.7 — отказ с указанием, что делать: модуль 3.x использует `nla_put_uint`, которого там нет, а запасного пути на 2.0 больше не существует |
| перезагрузки | апстрим перезагружался **безусловно** после шагов 1 и 2, полагаясь на возобновление по `STATE_FILE`. У нас осталась одна и осмысленная: модуль собран под другое ядро, чем работает сейчас |
| диагностика загрузки модуля | `load_amneziawg_module` различает три исхода: загрузился, поможет перезагрузка, не поможет никогда (Secure Boot). Прежний код глушил stderr `modprobe` и любой отказ объявлял следствием обновления ядра — при включённом Secure Boot это давало бесконечный круг перезагрузок |
| проверка `apt update` | `apt-get update` возвращает 0, даже не скачав ни одного индекса. Смотрим на результат (`apt_lists_usable`), а не на код возврата, и называем недоступные хосты — иначе установка падала минутой позже на «Unable to locate package gpg» |
| `secure_files` | вместо `keys/` и файла настроек — каталоги клиентов (700) и файлы `.private`/`.public` (600) |
| `create_diagnostic_report` | дополнительно скрываются `HeaderProtectionKey` и `PresharedKey` — по ним восстанавливается доступ к туннелю, а отчёт часто уходит в issue |
| хвост скрипта | вместо state-машины `while (( current_step < 99 ))` — линейный `main()` |

## Что умеет `awg3.sh`

Скрипт вырос из генератора параметров в инструмент управления сервером.

- **Интерфейсы.** `iface` — список, `iface add` — создать (имя берётся первое
  свободное), `iface remove` — снести вместе с ключами. Каждый интерфейс
  независим: свой порт, подсеть, общие параметры и каталог ключей
  `~/awg/<интерфейс>/<имя>/`. Прежние имена `ifaces` и `server-init` остались
  псевдонимами.
- **Только 3.1.** `RandomTrailers` и `DisableCookies` пишутся всегда,
  `PersistentKeepalive` — диапазоном, версии модуля и tools проверяются до
  записи конфига. Интерфейс, созданный до 3.1, опознаётся, и выдать на нём
  ключ нельзя: рассинхрон `RandomTrailers` рвёт туннель молча, без единой
  ошибки. Лечится `server-rekey`.
- **Переезд ключа** между интерфейсами с сохранением пары ключей
  (`migrate-client`): на исходном интерфейсе ключ остаётся, поэтому прежняя
  ссылка работает, пока человек не импортирует новую.
- **Системные обязанности, которые следуют из конфигурации:** порт в `ufw` и
  снятие глобального отключения IPv6 в `sysctl`, если IPv6 нужен в туннеле.
- **`peers`** — тот же список, что `list`, но колонками через табуляцию: для
  панели и скриптов. Выровненный вывод пришлось бы разбирать по ширине полей.
- **Пересоздания одной командой нет.** `server-init --force` менял разом
  ключи сервера, параметры обфускации и транспорт, а изменения не доезжали до
  работающего интерфейса. Пересоздать — это `iface remove` и `iface add`.

## Что осознанно НЕ переносилось

- ARM-сборки: готовые пакеты из чужого релиза собраны из 2.0-тега и с tools
  3.1 не работают. На ARM идёт обычный DKMS;
- поддержка ядер старше 6.7 — вместе с модулем 2.0, ради которого она была.
