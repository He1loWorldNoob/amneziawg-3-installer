# Установка от и до

От пустого сервера до ключа в телефоне — четыре команды, каждая со своей
задачей. Здесь весь путь: что спросят, что произойдёт и что делать, если
что-то пойдёт не так.

Дальнейшая эксплуатация — управление ключами, интерфейсами, бэкапы, смена
параметров — в [руководстве](usage.md).

---

## Что понадобится

Всё выполняется на самом сервере. Копировать что-либо с локальной машины не
нужно.

| Требование | Как проверить |
|---|---|
| Debian 12/13 или Ubuntu 22.04+ | `cat /etc/os-release` |
| **Ядро 6.7 или новее** | `uname -r` |
| Обычная ВМ, не LXC-контейнер | `systemd-detect-virt` → `kvm`, `qemu`, `none` |
| **Secure Boot выключен** | `mokutil --sb-state` |
| Свободно ≥ 2 ГБ | `df -h /` |
| Доступ root по SSH | вход работает |
| Клиент Amnezia VPN 5.0.1.5+ | на устройстве, куда пойдёт ключ |

**Почему ядро 6.7.** Модуль AmneziaWG 3.x использует `nla_put_uint` — эта
функция появилась в ядре 6.7. На более старом сборка не проходит, и установщик
останавливается до того, как что-то менять. Debian 12 приезжает с ядром 6.1:
там нужно ядро из `bookworm-backports` либо система посвежее.

**Почему Secure Boot.** Модуль собирается через DKMS и не подписан. При
включённом Secure Boot ядро откажется его грузить:

```
modprobe: ERROR: could not insert 'amneziawg': Key was rejected by service
```

Выключите его в BIOS/UEFI: в Proxmox это Hardware → EFI Disk, снять
pre-enrolled keys. Альтернатива — enroll собственного MOK-ключа, но это
интерактивная процедура при каждой загрузке.

## Три скрипта, три задачи

Одной командой всё сразу — нельзя, и это намеренно: у каждого шага своя цена
ошибки и своё место для отката. Граница проходит по вопросу «чьё это решение».

| Скрипт | Отвечает за |
|---|---|
| `bootstrap.sh` | Как настроена машина: пользователь, порт SSH, фаервол, fail2ban, обновление системы, swap, sysctl |
| `install-awg3.sh` | Пакеты AmneziaWG, модуль ядра, `awg3` в `PATH`. Больше ничего |
| `awg3` | Интерфейсы и ключи: создать, выдать, переселить, сменить параметры |

Каждый шаг качает свои файлы — скачивать одно и то же дважды не приходится.
Репозиторий целиком нужен только для тестов и панели.

---

## Шаг 1 — подготовка сервера

`bootstrap.sh`, под root, примерно пять минут.

Шаг необязателен, если система уже подготовлена по-своему. Тогда начинайте со
второго — но фаервола на машине не будет, и порт VPN окажется открыт просто
потому, что закрывать его некому.

```bash
curl -fsSLO https://raw.githubusercontent.com/He1loWorldNoob/amneziawg-3-installer/main/bootstrap.sh
sudo bash bootstrap.sh --user vpnadmin --ssh-port 2222 --disable-root-ssh yes
```

Скрипт спросит пароль нового пользователя дважды, а перед отключением root
остановится и потребует проверить новый доступ:

```
СЕЙЧАС БУДЕТ ОТКЛЮЧЁН ВХОД ROOT ПО SSH.
Текущая сессия жива, но НЕ ЗАКРЫВАЙТЕ ЕЁ.
Откройте ВТОРОЕ окно терминала и проверьте:

    ssh -p 2222 vpnadmin@203.0.113.10
    sudo -v

Вход и sudo работают? Введите yes целиком:
```

Откройте второе окно, проверьте — и только тогда отвечайте `yes` целиком, не
`y`. Любой другой ответ оставит root включённым: ничего страшного, закроете
потом вручную.

Итог сохранится в `~/awg3-bootstrap-summary.txt`. **Пароль восстановить
нельзя** — сохраните его.

### Что он ещё делает

- обновляет систему и ставит базовые пакеты;
- поднимает `ufw`: политики, лимит на порт SSH — и закрывает старый порт после
  подтверждения;
- настраивает fail2ban для SSH;
- создаёт swap, тюнит сетевую карту, пишет sysctl (BBR, защитные параметры);
- сносит лишние для сервера пакеты.

Ничего из этого не нужно — добавьте `--no-tweaks`.

### Вход по паролю

Разрешается намеренно: скрипт заводит пользователя именно с паролем и дважды
его спрашивает. Если бы `sshd` пароль не принимал — а облачные образы Debian и
Ubuntu приходят с `PasswordAuthentication no`, — войти им было бы нельзя нигде,
и узнали бы вы об этом уже отключившись.

Вход root при этом закрыт, а против перебора работают нестандартный порт,
`ufw limit` и fail2ban. Настройки лежат в
`/etc/ssh/sshd_config.d/00-awg3.conf`; если пароль не нужен вовсе, поменяйте
строку на `PasswordAuthentication no` после того, как проверите вход по ключу.

### Перезагрузка

Если обновилось ядро, в итоге будет строка:

```
Обновилось ядро — перезагрузите сервер: sudo reboot
```

Перезагрузитесь до второго шага. Иначе DKMS соберёт модуль под новое ядро, а
работать будет старое — и установщик попросит ребут уже сам.

## Шаг 2 — установка AmneziaWG

`install-awg3.sh`, под новым пользователем, примерно две минуты.

```bash
ssh -p 2222 vpnadmin@СЕРВЕР

B=https://raw.githubusercontent.com/He1loWorldNoob/amneziawg-3-installer/main
curl -fsSLO $B/install-awg3.sh -O $B/awg3.sh
chmod +x install-awg3.sh awg3.sh
sudo ./install-awg3.sh
```

Ставит пакеты, собирает модуль ядра через DKMS и кладёт `awg3` в `PATH`.
**Про VPN не спрашивает ничего** — сервера после него ещё нет. Два файла нужны
рядом: установщик кладёт `awg3.sh` в `~/awg` и делает симлинк
`/usr/local/sbin/awg3`.

Заканчивается так:

```
AmneziaWG установлен. Сервера ещё нет — его создаёт awg3.

ДАЛЬШЕ:
  sudo awg3 server-init      создать интерфейс (спросит параметры)
  sudo awg3 add ИМЯ          выдать ключ
```

### Единственная перезагрузка

Она нужна в одном случае: модуль собран под другое ядро, чем работает сейчас.
Скрипт скажет об этом и завершится — перезагрузитесь и запустите *ту же*
команду, установка продолжится с нужного места.

Опции немногочисленны, потому что настраивать здесь нечего:

| Опция | Смысл |
|---|---|
| `--awg-dir PATH` | каталог данных (по умолчанию `~/awg` текущего пользователя) |
| `--uninstall` | снести AmneziaWG |
| `--diagnostic` | собрать диагностический отчёт |
| `-y, --yes` | не задавать вопросов |

## Шаг 3 — создать интерфейс

`awg3 server-init`. Здесь задаются все параметры VPN.

```bash
sudo awg3 server-init
```

```
Параметры интерфейса awg0. Enter оставляет значение в скобках.

  UDP-порт [Enter — случайный]:
  Подсеть туннеля [10.9.9.1/24]:
  MTU [1280]:
  Изолировать клиентов друг от друга? [y/N]:
  Включить IPv6 в туннеле? [y/N]:
  Профиль мимикрии quic|tls|dtls|sip|dns|noise [quic]:
  Интенсивность low|medium|high [medium]:
  Имя хоста [Enter — определить внешний IP]:
```

То же самое одной строкой, без вопросов:

```bash
sudo awg3 server-init -y --awg-port 48872 --subnet 10.9.9.1/24 \
    --isolation off --ipv6 off -p quic -i medium --endpoint vpn.example.com
```

### Что стоит заполнить осмысленно

- **Порт** — случайный лучше предсказуемого: постоянный порт сам по себе
  признак.
- **Имя хоста** — если у сервера есть DNS-имя, укажите его. При смене IP
  выданные ключи продолжат работать.
- **Изоляция** — `on`, если клиенты не должны видеть друг друга внутри
  туннеля.
- **Профиль мимикрии** — свойство отправляющей стороны, у каждого ключа может
  быть свой.

Порт в `ufw` открывается сам. Если попросили IPv6 в туннеле — снимается и его
глобальное отключение в `sysctl`: иначе `awg-quick` не смог бы назначить
интерфейсу IPv6-адрес.

## Шаг 4 — выдать ключ

```bash
sudo awg3 add my_phone
```

```
[ OK ] клиент 'my_phone' создан: 10.9.9.2
  каталог: /home/vpnadmin/awg/awg0/my_phone
  конфиг: .../my_phone.conf
  ссылка: .../my_phone.vpnuri
  профиль обфускации: AWG 3.1 / quic / medium
```

В каталоге ключа пять файлов:

| Файл | Для чего |
|---|---|
| `ИМЯ.conf` | импорт в приложение файлом |
| `ИМЯ.png` | QR-код — навести камерой из приложения |
| `ИМЯ.vpnuri` | ссылка `vpn://` — открывается приложением Amnezia |
| `ИМЯ.private`, `ИМЯ.public` | пара ключей клиента |

Забрать на свою машину:

```bash
scp -P 2222 -r vpnadmin@СЕРВЕР:~/awg/awg0/my_phone ./
```

Или через панель — она скачивает conf, QR и ссылку одним подключением.

### Что где лежит

Всё внутри `~/awg`: журнал, бэкапы и по каталогу на интерфейс. Ключ — ещё
уровнем ниже, в собственном каталоге, чтобы отдать его целиком одной папкой.

```
~/awg/
├── awg3.sh
├── awg0/
│   ├── my_phone/my_phone.conf .png .vpnuri .private .public
│   └── server_private.key  server_public.key
├── awg1/
├── awg3.log
└── backups/
```

### Нужен клиент 5.0.1.5 или новее

Интерфейс всегда 3.1: `RandomTrailers` и `DisableCookies` пишутся обеим
сторонам, `PersistentKeepalive` — диапазоном. Приложение постарше эти
параметры не знает и конфиг не примет.

## Несколько интерфейсов

Интерфейсы независимы: свой порт, подсеть, общие параметры и каталог ключей.
Держать второй полезно про запас — если один попадёт под блокировку по набору
параметров, второй уже поднят, с другими `S1-S4` и другим портом.

```bash
sudo awg3 iface                                              # список
sudo awg3 iface add --awg-port 51840 --subnet 10.9.1.1/24    # создать
sudo awg3 --iface awg1 add ivan                              # ключ на нём
sudo awg3 iface remove awg1                                  # снести с ключами
```

`--iface` адресует любую команду конкретному интерфейсу и принимается как
перед ней, так и после. Без него всё уходит на `awg0`. Имя при создании можно
не задавать — возьмётся первое свободное.

### Переезд ключа без простоя

```bash
sudo awg3 --iface awg0 migrate-client ivan --to awg1
```

Ключ заводится на `awg1` с **той же парой ключей**: на сервере это остаётся тот
же пир, у человека — та же личность. Меняются порт, адрес в туннеле и общие
параметры.

С исходного интерфейса ключ намеренно **не** удаляется. Пока он там есть,
прежняя ссылка работает, и человек переезжает в тот момент, когда сам
импортирует новую. Когда переехал — уберите старого:

```bash
sudo awg3 --iface awg0 remove ivan
```

## Панель с Windows

Необязательна: всё то же самое делается командой `awg3` на сервере. Но если не
хочется каждый раз ходить по SSH — в [`panel/`](../panel/) лежит интерактивное
меню. Запускается двойным щелчком по `awg-panel.bat`, ничего ставить не нужно:
работает на встроенных в Windows PowerShell и `ssh`.

```
СЕРВЕРЫ                          ИНТЕРФЕЙСЫ
 1  Домашний   admin@vpn1:2222    1  awg0  48872  10.9.9.1/24  3.1  2  active
    интерфейсов: 2, ключей: 3     2  awg1  51840  10.9.1.1/24  3.1  1  active
 N  добавить сервер               N  создать    D  удалить
 Q  выход                         0  назад к серверам

КЛЮЧИ ИНТЕРФЕЙСА awg0            КЛЮЧ my_phone
 1  my_phone  10.9.9.2  активен     адрес:     10.9.9.2/32
 2  laptop    10.9.9.3  3ч назад    совместим: да
 N  создать   D  удалить            трафик:    принято 1.2 ГБ, отдано 340 МБ

                                    1 скачать     2 ссылка vpn://
                                    3 переселить  4 удалить
```

Навигация вглубь: серверы → интерфейсы → ключи → карточка ключа. Возврат назад
везде `0`, выход `Q`. Пароль нужен один раз — при добавлении сервера, и
спрашивает его сам `ssh`: панель его не видит и не хранит. Дальше вход по
ключу, который она заводит сама, и право запускать без пароля выдаётся
**только** на `awg3.sh`.

Подробности — в [`panel/README.md`](../panel/README.md).

## Если что-то не так

### Модуль не грузится: Key was rejected by service

Включён Secure Boot. Проверьте `mokutil --sb-state` и выключите его в
прошивке — перезагрузка тут не поможет никогда, и скрипт скажет об этом прямо,
а не отправит по кругу.

### Модуль собран под другое ядро

Ядро обновилось, а работает старое. Перезагрузитесь и запустите ту же команду
установки — она продолжит с нужного места.

### apt не скачал ни одного индекса

Установщик остановится и назовёт хосты, до которых не достучался. Обычно это
недоступное из вашей сети зеркало: замените его в `/etc/apt/sources.list` — на
Debian 13 это `/etc/apt/mirrors/debian.list` — и повторите.

### Клиент не подключается

```bash
sudo awg3 list              # колонка СОВМЕСТИМ
sudo ufw status | grep udp
sudo ss -ulnp | grep awg
```

`нет — клиент не подключится` означает, что конфиг выдан до смены общих
параметров: удалите ключ и выдайте заново. Иначе смотрите на порт — закрыт у
провайдера, — или на `Endpoint` в конфиге клиента.

### «Интерфейс создан до 3.1»

Так выглядит сервер, развёрнутый прежними версиями: в его конфиге нет
`RandomTrailers`. Выдать на нём ключ 3.1 нельзя — туннель молча не встанет.
Лечится одной командой, и она же единственная:

```bash
sudo awg3 --iface awg0 server-rekey
```

После неё ключи выдаются заново — параметры интерфейса общие для всех.

### Потерян доступ по SSH

Старый порт закрывается только после того, как вы подтвердите новый доступ
словом `yes`. Если всё же заперлись — консоль гипервизора и
`/etc/ssh/sshd_config.d/00-awg3.conf`: там лежат порт и разрешение входа по
паролю.
