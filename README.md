# amneziawg-3-installer

Развёртывание AmneziaWG 3.1 на сервере с полного нуля: подготовка системы,
установка AmneziaWG, создание 3.1-конфигурации и управление клиентами.

Три скрипта, три задачи: `bootstrap.sh` готовит систему, `install-awg3.sh`
ставит AmneziaWG, `awg3` создаёт и ведёт интерфейсы. Промежуточных версий
протокола нет — интерфейс всегда 3.1.

Проверено на Ubuntu 24.04 и Debian 13: развёртывание с нуля, подключение
клиента с реальным трафиком, обновление ядра с пересборкой модуля,
перезагрузка, удаление.

## Состав

| Файл | Назначение |
|---|---|
| `bootstrap.sh` | подготовка свежего сервера: обновление системы, `sudo`-пользователь, порт SSH, отключение root, фаервол, fail2ban, swap, sysctl |
| `install-awg3.sh` | пакеты AmneziaWG, DKMS-модуль, `awg3` в `PATH`. Ни систему, ни фаервол, ни сервер не настраивает. Форк [bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer) v5.23.0 |
| `awg3.sh` | интерфейсы и клиенты: `server-init`, `add`, `remove`, `link`, `list`, `stats`, `backup`, `show`, `restart`, `ifaces`, `migrate-client`, `server-rekey` |
| `panel/` | необязательная панель управления с Windows: то же самое, но меню вместо SSH-команд |

## Требования

- Debian 12/13 или Ubuntu 22.04+
- **ядро 6.7 или новее** — модуль 3.x использует `nla_put_uint`, которого в
  более старых ядрах нет. Debian 12 приезжает с 6.1: нужно ядро из
  `bookworm-backports` либо система посвежее
- root-доступ на старте
- поддержка DKMS: обычная ВМ, не LXC-контейнер
- **Secure Boot должен быть выключен** — иначе ядро отвергнет неподписанный
  DKMS-модуль (`Key was rejected by service`)

## Быстрый старт

Всё выполняется на самом сервере. Скачайте репозиторий:

```bash
# вариант без git — на свежем сервере его может не быть
curl -fsSL https://github.com/He1loWorldNoob/amneziawg-3-installer/archive/refs/heads/main.tar.gz \
  | tar -xz && cd amneziawg-3-installer-main

# либо, если git есть
git clone https://github.com/He1loWorldNoob/amneziawg-3-installer.git
cd amneziawg-3-installer
```

Три команды, у каждой своя задача, и каждая качается своим шагом — повторять
загрузку не нужно. Между первой и второй — переподключение под новым
пользователем: это и есть проверка, что доступ работает, до того как root будет
закрыт.

```bash
# 1. подготовка системы — один самодостаточный файл, под root
curl -fsSLO https://raw.githubusercontent.com/He1loWorldNoob/amneziawg-3-installer/main/bootstrap.sh
sudo bash bootstrap.sh --user vpnadmin --ssh-port 2222 --disable-root-ssh yes

# переподключиться: ssh -p 2222 vpnadmin@СЕРВЕР

# 2. установка AmneziaWG: пакеты и модуль ядра, больше ничего.
#    Нужны два файла рядом — установщик кладёт awg3.sh в ~/awg
curl -fsSLO https://raw.githubusercontent.com/He1loWorldNoob/amneziawg-3-installer/main/install-awg3.sh      -O https://raw.githubusercontent.com/He1loWorldNoob/amneziawg-3-installer/main/awg3.sh
chmod +x install-awg3.sh awg3.sh
sudo ./install-awg3.sh

# 3. создать интерфейс — спросит порт, подсеть, IPv6 и остальное
sudo awg3 server-init

# и выдать клиента: QR и ссылка vpn:// лягут рядом с конфигом
sudo awg3 add my_phone
```

Целиком репозиторий нужен только для тестов и панели.

Перезагрузка может понадобиться после первого шага — если обновилось ядро.
Второй шаг просит её только в одном случае: модуль собран под другое ядро, чем
работает сейчас.

Всё без вопросов:

```bash
sudo ./install-awg3.sh --yes
sudo awg3 server-init -y --awg-port 48872 --subnet 10.9.9.1/24 --isolation off
sudo awg3 add my_phone -y
```

Пароль в `bootstrap.sh` передаётся только файлом или интерактивно — аргументы
командной строки видны в `ps` любому пользователю системы.

## Как это устроено

**Единственный источник истины — `/etc/amnezia/amneziawg/awg0.conf`.**
Отдельного файла настроек нет: порт, подсеть, MTU, изоляция клиентов и IPv6
читаются из самого конфига, поэтому расходиться с реальностью нечему.

Все данные лежат в `~/awg`: журнал, бэкапы и по каталогу на интерфейс. Клиент —
ещё уровнем ниже, в собственном каталоге, чтобы отдать его целиком одной папкой:

```
~/awg/
├── awg3.sh
├── awg0/
│   ├── my_phone/my_phone.conf  .png  .vpnuri  .private  .public
│   └── my_laptop/…
├── awg1/
│   └── ivan/…
└── backups/
```

Раскладка по интерфейсам, а не вперемешку, снимает и столкновение имён: клиент,
названный `awg1`, иначе занял бы каталог интерфейса.

`ИМЯ.vpnuri` — ссылка `vpn://` для импорта в приложение AmneziaVPN. Она
собирается из того же конфига, поэтому конфиг и ссылка не расходятся;
`awg3 link ИМЯ` пересобирает её для клиентов, выданных раньше.

Каталог данных вычисляется: домашний каталог того, кто запустил через `sudo`,
либо `/root/awg` при работе под root. Перекрывается `--awg-dir`.

`bootstrap.sh` устроен так, чтобы не отрезать вас от сервера: старый и новый
порты SSH открыты одновременно, конфигурация проверяется через `sshd -t` до
перезапуска, после перезапуска скрипт убеждается через `ss`, что порт реально
слушается, и откатывается, если нет. Вход root закрывается только после того,
как вы вручную подтвердите работу нового доступа словом `yes` целиком.

## Профиль мимикрии

Профиль (`quic`, `tls`, `dtls`, `sip`, `dns`, `noise`) — свойство
**отправляющей** стороны, а не общий параметр. Совпадать на обоих концах
обязаны только `S1-S4`, `H1-H4` и `HeaderProtectionKey`.

Поэтому у сервера свой набор `I1-I5`, а каждый `awg3 add -p tls` создаёт
клиента со своим — одинаковые наборы у всех устройств сами по себе являются
отпечатком.

## Что даёт 3.1

`RandomTrailers` дописывает к служебным пакетам случайный хвост: без него длина
рукопожатия постоянна и сервер опознаётся по одному пакету. Параметр **обязан
совпадать** на сервере и всех его клиентах — включённый на одной стороне он
рвёт туннель целиком. `DisableCookies` запрещает отвечать на cookie-запросы и,
наоборот, односторонний.

Выключателей у них нет: 3.0 из проекта убран. Нужен клиент Amnezia 5.0.1.5+, а
на сервере модуль и `amneziawg-tools` версии 3.1 — версии проверяются до записи
конфига. Интерфейс, созданный до 3.1, `awg3` опознаёт и не даёт выдать на нём
клиента, пока не прошёл `server-rekey`: рассинхрон `RandomTrailers` рвёт туннель
молча, без единой ошибки.

Интерфейсов может быть несколько, и они независимы: свой порт, подсеть, общие
параметры и каталог клиентов (`~/awg` у `awg0`, `~/awg1` у `awg1`).

```bash
sudo awg3 --iface awg1 server-init --awg-port 51840 --subnet 10.9.1.1/24
sudo awg3 ifaces
sudo awg3 --iface awg0 migrate-client ivan --to awg1
```

Порт в `ufw` и, если нужен IPv6, снятие его глобального отключения в `sysctl` —
тоже работа `server-init`: он один знает, какой порт у какого интерфейса.

`migrate-client` заводит клиента на другом интерфейсе с тем же ключом и
**не удаляет** его со старого: прежняя ссылка работает, пока человек не
импортирует новую, — переезд обходится без простоя.

## Управление с Windows

Если не хочется каждый раз ходить по SSH, в [`panel/`](panel/) лежит
интерактивная панель: список клиентов, трафик, создание и удаление ключей,
скачивание `.conf`, QR и ссылки `vpn://` прямо к себе, бэкапы, перезапуск
сервиса.

Запускается двойным щелчком по `awg-panel.bat` и ничего не требует ставить:
работает на встроенных в Windows PowerShell и `ssh`. Пароль нужен один раз,
при добавлении сервера, и спрашивает его сам `ssh` — панель его не видит и не
хранит; дальше вход идёт по ключу. Каждое действие — отдельное SSH-подключение.
Подробности — в [`panel/README.md`](panel/README.md).

Панель необязательна: всё то же самое делается командой `awg3` на сервере.

## Тесты

```bash
sudo apt-get install -y bats shellcheck
./tests/run.sh          # shellcheck + все юнит-тесты
./tests/run.sh postup   # только tests/unit/postup.bats
```

239 юнит-тестов. Плюс интеграционные прогоны на живых Ubuntu 24.04 и
Debian 13, включая реальное подключение клиента и проверку после
перезагрузки — журнал и список найденных ими дефектов в
[`tests/integration/README.md`](tests/integration/README.md).

Каталог `tools/` — вспомогательные скрипты для разработки: они поднимают
одноразовую виртуалку в Proxmox и доставляют туда рабочую копию. Для
установки на реальный сервер не нужны.
