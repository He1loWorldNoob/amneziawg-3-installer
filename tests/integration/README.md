# Интеграционные прогоны

Стенд: Ubuntu 24.04.4 LTS в Proxmox (KVM), 1 ГБ RAM, ядро 6.8.0-137,
`ssh.socket` активен, Secure Boot выключен. Каждый прогон — с клона шаблона,
то есть с одинакового исходного состояния.

Дата: 2026-08-05.

## Результаты

| # | Сценарий | Итог |
|---|---|---|
| 1 | `--mode awg-only`, два клиента | пройден: модуль `3.0.20260731-04` собран и загружен, `awg0` поднят, UFW открыл только SSH и порт VPN |
| 2 | `--mode full`, новый пользователь, порт 2222, root отключается | пройден: вход `admin` на новом порту, `permitrootlogin no`, старый порт закрыт, данные в `/home/admin/awg` |
| 3 | Чисто-root установка | пройден: `AWG_DIR` = `/root/awg`, клиент создан |
| 4 | Полностью неинтерактивный (`--yes` + все флаги) | пройден: ни одного вопроса |
| 5 | Повторный запуск поверх установленного | пройден: понятное сообщение с подсказками, код возврата 0, сервер не тронут |
| 6 | Изоляция `on` через `reinstall` | пройден: правило `FORWARD -i awg0 -o awg0 -j DROP` появилось, пиры целы |
| 7 | IPv6 `on` | пройден после исправления: `fddd:2c4:2c4:2c4::1/64` на интерфейсе, `ip6tables` MASQUERADE, sysctl снят |
| 8 | Сбой посреди работы | пройден: отказ до изменений, конфиг и пиры целы |
| 9 | `--uninstall` | пройден: AWG снесён, SSH-порт, пользователь и фаервол не тронуты |
| 10 | Перезагрузка | пройден: туннель поднимается сам, модуль загружен, NAT восстановлен |
| 11 | **Реальное подключение клиента** | пройден: вторая ВМ подключилась, рукопожатие, 0% потерь до сервера и в интернет |

## Дефекты, найденные прогонами

Ни один из них не ловился юнит-тестами — все требовали живой системы.

| Дефект | Последствие |
|---|---|
| Безусловная перезагрузка после шагов 1 и 2 | установка не заканчивалась никогда: цикл перезагрузок |
| `ufw: ERROR: Bad port` | установка падала: порт открывался до того, как его выбирал `server-init` |
| `SCRIPT_DIR` не разыменовывал симлинк | `awg3 list` показывал пустой список: каталогом считался `/usr/local/sbin` |
| `AllowedIPs = ::/0` у клиента без IPv6 | **туннель не поднимался вообще**: `awg-quick` падал с «IPv6 is disabled on nexthop device» |
| `useradd` и системная группа `admin` | развёртывание на Ubuntu ломалось на дефолтном `--user admin` |
| Перезапуск `ssh.service` при socket activation | после смены порта SSH отвечал «Connection refused»: два слушателя на одном порту |
| `systemctl stop ssh.service` | обрывал текущую SSH-сессию вместе со скриптом |
| `ListenStream=ПОРТ` без явного адреса | сокет слушал только IPv6, IPv4 — никто |
| `--yes` не доходил до `bootstrap.sh` | root молча оставался включённым вопреки `--disable-root-ssh yes` |
| Каталог данных у запустившего sudo | клиенты попадали в `/home/user/awg` вместо `/home/admin/awg` |
| Каталог оставался `root:root` | пользователь не мог забрать свои конфиги без `sudo` |
| `--ipv6 on` при отключённом в sysctl IPv6 | **сервер не поднимался**: сервис в `failed` |

## Как повторить

```powershell
.\tools\vm.ps1 -Action recreate -Id 1012      # клон шаблона, ждёт SSH
.\tools\sync.ps1 -Vm user@10.10.10.101        # доставка одним соединением
ssh user@10.10.10.101 'cd ~/awg3-deploy && ./tests/run.sh'
```

Доставка идёт одним SSH-соединением намеренно: установщик ставит
`ufw limit 22/tcp`, и десяток отдельных `scp` блокирует сам себя.

После смены порта добавляйте `-Port 2222`.
